# UE5 FPS 联机 Demo 与城市级三维场景扩展

本项目基于 Unreal Engine 5 的 First Person 模板开发，完成了一个可联机的
第一人称射击 Demo，覆盖角色移动、视角控制、射击、换弹、受击、死亡重生
和多人同步等基础玩法。在此基础上，又叠加了城市级三维资产渲染测试与
GIS / 数字孪生方向的扩展包装，用于展示大规模场景漫游、空间测距和坐标
转换等能力。

> 本项目为腾讯游戏「开局一课」客户端开发方向结业项目，已通过结业考核。

## 技术栈

- 引擎：Unreal Engine 5.7
- 开发：C++ / 蓝图混合开发
- 城市资产扩展：Manama Bahrain 3D City Map Model（Fab）
- 三维渲染：实时渲染管线、光照、材质、后期处理
- GIS 扩展：经纬度锚点、世界坐标转换、POI 标注、空间测距
- 工程：Git 版本管理与模块化 C++ 代码组织

## 核心功能

| FPS 联机玩法 |
- 第一人称视角场景漫游（WASD 移动 + 鼠标视角控制）
- 射击、换弹、受击、死亡重生
- 支持多客户端同时连接测试
- 玩家状态实时同步
- PIE（Play In Editor）双窗口对战测试通过

| 城市级三维资产测试 |
- 基于 Fab 资产 Manama Bahrain 3D City Map Model 设计导入与测试流程
- 导入城市级三维资产（建筑白模、道路网、水系、绿地），测试大规模
  场景下的实时渲染性能
- 调整材质、光照与后期处理参数，优化城市场景渲染效果
- 在城市场景中验证第一人称漫游与空间碰撞检测功能

| GIS / 数字孪生扩展 |
- 使用 `GISDigitalTwinSubsystem` 管理场景地理原点和经纬度到 UE 世界坐标的转换
- 使用 `GISCityAssetAnchor` 记录城市资产来源、覆盖范围、锚点坐标和优化策略
- 使用 `GISPointMarker` 表示商业区、道路节点、水系节点、地标建筑等兴趣点
- 使用 `GISMeasurementTool` 支持三维距离和水平距离测量

## 运行方式

1. 使用 Unreal Engine 5.x 打开 `UE5GISScene.uproject`
2. 如有 C++ 代码，点击编译
3. 打开主关卡，点击 Play 运行
4. 多窗口测试：将 Number of Players 设为 2，Play Mode 设为 New Editor Window (PIE)

## 遇到的问题与解决

### 问题1：大世界坐标下的浮点精度与位置抖动

*问题描述：*
当场景范围较大或物体远离世界原点时，物体出现位置抖动、渲染异常
等现象，移动越远越明显。

*原因分析：*
UE5 默认使用单精度浮点（float）存储世界坐标，当坐标数值较大时，
浮点精度不足以表示微小位移，导致每帧计算的位置出现误差，表现为
视觉抖动。这与 GIS 中大范围投影坐标下的精度损失问题本质相同。

*解决方案：*
- 采用场景分区策略，将大场景拆分为多个子区域，控制单个区域的
  坐标范围；
- 对关键计算使用双精度（double）中间变量，减少累积误差；
- 理解引擎的原点重定向（Origin Rebase）机制，在需要超大世界
  时通过动态平移原点保持坐标精度。

---

### 问题2：射线检测（Line Trace）的命中精度与漏检

*问题描述：*
使用射线检测实现空间交互与命中判定时，高速移动的小体积物体
经常出现漏检，明明应该命中却没有触发事件。

*原因分析：*
射线检测是离散的逐帧采样，物体在两帧之间移动距离过大时，射线
可能在两帧之间"穿过"物体而未检测到碰撞。这与 GIS 中矢量叠加
分析时的采样精度问题类似——采样间隔过大导致细小地物被遗漏。

*解决方案：*
- 对高速物体增加检测频率，在一帧内进行多次子步长（sub-step）
  检测；
- 将纯射线检测改为球形检测（Sphere Trace）或胶囊体检测，
  增大检测体积，降低漏检率；
- 调整碰撞体（Collision）尺寸，使其与视觉模型匹配，避免
  碰撞体过小导致的检测失效。

---

### 问题3：多坐标系转换——世界坐标、本地坐标与屏幕坐标

*问题描述：*
开发中需要在世界坐标、组件本地坐标和屏幕坐标（UI坐标）之间
频繁转换，初期对各坐标系的定义和变换关系理解不清，导致
UI 标记位置与 3D 物体实际位置不匹配。

*原因分析：*
UE5 中存在多套坐标系：世界坐标是全局绝对坐标，本地坐标是
相对于父组件的相对坐标，屏幕坐标是 2D 投影后的像素坐标。
三者之间需要通过变换矩阵和投影/反投影操作进行转换，这与
GIS 中地理坐标、投影坐标和屏幕像素坐标之间的变换完全对应。

*解决方案：*
- 理清各坐标系的定义与层级关系，本地坐标通过组件变换矩阵
  （Transform）转换为世界坐标；
- 使用 `ProjectWorldLocationToScreen` 将 3D 世界坐标投影为
  2D 屏幕坐标，实现 UI 标记跟随 3D 物体；
- 使用 `DeprojectScreenToWorld` 将屏幕坐标反投影为世界坐标
  射线，实现点击屏幕选取 3D 物体的功能；
- 理解投影变换矩阵的原理，确保坐标转换过程中深度信息正确。
